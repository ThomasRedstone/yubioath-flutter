# Unofficial Ubuntu Touch packaging

This is the Apache-2.0 Yubico app port, not an official Yubico UT product. Upstream branding and license remain intact. The UT target currently uses debug/JIT assets, not a production desktop binary. Upstream workflows pin Flutter 3.44.4; the bundled UT runtime must provide the exact same Flutter version and engine revision as the SDK used to build this app. Do not assume the locally installed runtime or the upstream workflow version matches.

From a clean clone with its pubspec.lock, provide a Flutter SDK and the verified runtime staging directory, then run:

```sh
python3 click-arm64/build-public.py --flutter-sdk /path/to/flutter --runtime-dir /path/to/verified-runtime --runtime-notices /path/to/matching-native-worker-notices --runtime-build-record /path/to/reviewed-arm-build.json --output /new/click-candidate
```

Requires public Flutter/Dart package access, Clickable >=8.8, Docker, Linux ARM64-compatible assets/native dependencies and the runtime SDK. The script refuses SDK/engine mismatches dirty SDK source or an existing output, enforces pubspec.lock, builds linux-arm64 debug bundle, records build metadata, includes upstream license and packages the click. Move older staged artifacts to a private backup before rebuilding. Native assets/plugins still require ARM64 ELF/ABI inspection; build success is not hardware acceptance. The package carries the exact runtime binaries, hash manifest and runtime license directory. Runtime corresponding source/build records and app notices remain release inputs.

Install dependency order: (1) verified Noble ARM64 ut-pcscd/libccid payload, (2) ut-yubioath-helper built for ARM64 CPython 3.12, (3) this app click containing matching flutter-ut-embedder runtime >=0.3.4 with schema1 runtime.json. Click manifests do not automatically install these dependencies. The launcher verifies metadata and required files, uses its own runtime directory and accepts YUBIOATH_HELPER_PATH for independently installed helpers, and passes a stable per-app storage identity. Keep helper RPC code from this same app source revision; cross-version protocol compatibility is unvalidated. See dependency repositories' removal/rollback guides; uninstall this app before removing helper/PCSC dependencies used by other apps.

Historical local OATH listing succeeded. TOTP generation, protected keys, QR import, disconnect/reconnect, FIDO/PIV, cancellation and upgrade remain separate acceptance gates. The upstream desktop support matrix does not imply UT support. Do not upload key serials, account data or live helper transcripts to issues; use synthetic fixtures. App data lives in its per-app runtime namespace/cache; removing the click should not silently delete accounts or settings. Permission/confinement and account storage need real-device review before recommending installation.

Source-only build without a matching runtime is explicit: `python3 click-arm64/build-public.py --flutter-sdk /clean/flutter --assets-only --output /new/assets-candidate`. Output must be absent; staged assets/metadata are atomically published. The builder includes the original Apache license and Flutter's generated NOTICES.Z and records current source dirty state; do not claim uncommitted packaging equals its recorded HEAD.

An isolated linux-arm64 debug source rebuild completed 2026-10-14 using reviewed Flutter 3.44.9/engine 5a2a6a42 and unchanged pubspec.lock. The new Noble click bundles the genuine source-built ARM64 runtime (unverified debug candidate), its original manifest, all supplied runtime license texts, and Flutter NOTICES.Z. Packaging pins ubuntu-touch-24.04-1.x / policy 2404.1. No absolute shared-runtime path remains; default Clickable review now reports only the unconfined template as a hard failure. The builder propagates that nonzero result. This is a research candidate, not an OpenStore-approved release. Older Focal/shared-runtime candidates are preserved for diagnosis and must not be distributed.

Bundling is deliberate: the app launch path resolves relative to its installed click, without trusting a mutable shared executable. The original runtime manifest and copied-file hashes preserve exact source/version alignment. This does not solve smartcard confinement. The helper remains an external CPython3.12 installation using PCSC/USB and SecretService paths. Inspection of the official Ubuntu 2404.1 AppArmor policy found no standard PCSC/USB/SecretService grants; its accounts group supports AccountsSSO/signond, which is a different service. Removing unconfined without a tested supported adapter would break functionality. Manual store/policy review or a maintained confined system service adapter is required; no profile weakening or skipped review constitutes success. See [Click security documentation](https://docs.ubports.com/en/latest/appdev/platform/click.html) and [official policy source](https://gitlab.com/ubports/development/core/apparmor-easyprof-ubuntu). Actual target permission/account-storage acceptance remains required.

Packaging also requires the matching native-worker notice inventory from ut-platform. The builder checks every component/stdlib notice hash and carries texts plus components.json and its Cargo.lock digest inside the app. Keep the matching source archive pack as a separate companion; do not strip it from the release source inventory. The build record must bind the runtime executable hash, ARM target, engine revision and Cargo.lock hash to the inventory; mismatches are refused. A truthful source build record remains a release prerequisite.
